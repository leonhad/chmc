# Internal CHM Index Formats

This document describes the internal files used by full-text search and keyword index in the CHM generated by `chm_builder`: `$FIftiMain`, `$OBJINST`, and the `$WW*` family.

The layouts below were inferred and validated from the Free Pascal code (`chmfiftimain.pas`, `htmlindexer.pas`), reference blobs from HTML Help Workshop/libmspack, and observed behavior in `hh.exe`. Fields marked as "unknown/reserved" are preserved by the builder with compatible observed values.

## Overview

| File | Function | Note |
|---|---|---|
| `$FIftiMain` | Full-text index (Full-Text Search) | Word tree + WLC (Word Location Codes). |
| `$OBJINST` | Objects/instances used by the index | Fixed-structure binary blob, with LCID. |
| `$WWKeywordLinks/BTree` | Keyword BTree | Words in UTF-16LE, 2048-byte blocks. |
| `$WWKeywordLinks/Data` | Keyword data | 13 bytes per entry. |
| `$WWKeywordLinks/Map` | BTree block map | Accumulated list of entries per listing block. |
| `$WWKeywordLinks/Property` | Keyword index properties | 8 DWORDs when there are keywords. |
| `$WWAssociativeLinks/Property` | ALinks properties | 4 zero bytes in the observed case. |
| `$WWAssociativeLinks/` | Logical directory | Empty directory entry. |
| `$WWKeywordLinks/` | Logical directory | Empty directory entry. |

The CHM also announces capabilities in the `#SYSTEM` entry with code `4`: the full-text field is non-zero when `$FIftiMain` exists; the KLinks field is non-zero when there are keywords.

## Conventions

- Little-endian integers, unless indicated.
- `DWORD` = uint32, `WORD` = uint16, `BYTE` = uint8.
- File offsets are absolute within the stream, unless indicated.
- `ENCINT-BE-7` here means compressed integer in 7-bit groups, with bit 7 as continuation, **little-endian group order**: first byte carries bits 0..6, second 7..13, etc. This is the format used by FPC's `WriteCompressedIntegerBE` for `$FIftiMain`.
- `ENCINT dir` is the compressed integer of the CHM/PMGL directory (big-endian by 7-bit groups), **not** used inside `$FIftiMain`.

## `$WWKeywordLinks/*`

The `$WWKeywordLinks` family implements the binary keyword index (`.hhk`). The builder creates the files only with entries that have resolvable `Name` and `Local` in `#TOPICS`.

### `$WWKeywordLinks/Data`

Fixed-record file, one per sorted keyword.

- Size: `13 * N`
- Order: case-insensitive by word; tie by original word.

| Offset | Size | Type | Description |
|---:|---:|---|---|
| 0x00 | 4 | DWORD | Observed value `0`. |
| 0x04 | 4 | DWORD | Total number of topics in the CHM (`#TOPICS`/total count). |
| 0x08 | 1 | BYTE | `0x80` observed. |
| 0x09 | 4 | bytes | Observed zeros. |

### `$WWKeywordLinks/BTree`

BTree in 2048-byte blocks, with a fixed 76-byte header.

#### BTree Header (76 bytes)

| Offset | Size | Type | Value/description |
|---:|---:|---|---|
| 0x00 | 2 | bytes | Signature `3B 29` (`";)"`). |
| 0x02 | 2 | WORD | Flags `0x0104` observed. |
| 0x04 | 2 | WORD | Block size: `2048`. |
| 0x06 | 3 | ASCII | `"X44"` observed. |
| 0x09 | 17 | bytes | Zeros/reserved. |
| 0x1A | 4 | DWORD | Last listing (leaf) block, or 0 if only one. |
| 0x1E | 4 | DWORD | Last index block, or 0/-1 depending on observed case. |
| 0x22 | 4 | DWORD | `0xFFFFFFFF`. |
| 0x26 | 4 | DWORD | Total number of blocks. |
| 0x2A | 2 | WORD | Tree depth. |
| 0x2C | 4 | DWORD | Total number of entries/keywords. |
| 0x30 | 4 | DWORD | Codepage: `1252`. |
| 0x34 | 4 | DWORD | LCID. |
| 0x38 | 4 | DWORD | `1`. |
| 0x3C | 4 | DWORD | `10031`. |
| 0x40 | 12 | bytes | Zeros/reserved up to 76 bytes. |

#### Listing Block (leaf)

| Offset | Size | Type | Description |
|---:|---:|---|---|
| 0x00 | 2 | WORD | Free space at the end of the block. |
| 0x02 | 2 | WORD | Number of entries in the block. |
| 0x04 | 4 | DWORD | Previous block, or `-1`. |
| 0x08 | 4 | DWORD | Next block, or `-1`. |
| 0x0C | ... | bytes | Listing entries. |
| ... | ... | bytes | Zeros up to 2048. |

#### Listing Entry

The word is stored as a UTF-16LE string terminated with `0x0000`, converted from CP1252.

| Field | Size | Type | Description |
|---:|---:|---|---|
| word | variable | UTF-16LE NUL | Keyword. |
| seeAlso | 2 | WORD | `0` when there is no "See Also". |
| depth | 2 | WORD | Depth/usage observed `0`. |
| commaCharIndex | 4 | DWORD | `0`. |
| unknown | 4 | DWORD | `0`. |
| pairCount | 4 | DWORD | Number of topic/entry pairs; builder uses `1`. |
| topicIndex | 4 | DWORD | Topic index in `#TOPICS`. |
| always1 | 4 | DWORD | `1` observed. |
| dataOffset | 4 | DWORD | Offset in the `Data` file, multiple of 13. |

#### Index Block

Used when there is more than one listing block. Structure similar to leaf:

| Offset | Size | Type | Description |
|---:|---:|---|---|
| 0x00 | 2 | WORD | Free space. |
| 0x02 | 2 | WORD | Number of entries. |
| 0x04 | 4 | DWORD | First child block of the level (observed). |
| 0x08 | ... | bytes | Index entries. |

Index entry: like the listing entry, but the last DWORD points to the child block instead of `dataOffset`.

### `$WWKeywordLinks/Map`

| Offset | Size | Type | Description |
|---:|---:|---|---|
| 0x00 | 2 | WORD | Number of listing blocks. |
| 0x02 | N*8 | bytes | For each block: `DWORD accumulatedEntriesBefore`, `DWORD blockNumber`. |

`accumulatedEntriesBefore` is the accumulated count before the block; the builder calculates by linear distribution of keywords across blocks.

### `$WWKeywordLinks/Property`

When there are keywords:

| Offset | Size | Type | Value |
|---:|---:|---|---:|
| 0x00 | 4 | DWORD | 0 |
| 0x04 | 4 | DWORD | 0 |
| 0x08 | 4 | DWORD | 0 |
| 0x0C | 4 | DWORD | 0x0C |
| 0x10 | 4 | DWORD | 1 |
| 0x14 | 4 | DWORD | 1 |
| 0x18 | 4 | DWORD | 0 |
| 0x1C | 4 | DWORD | 0 |

When there are no keywords, the file can be 4 zero bytes.

## `$WWAssociativeLinks/*`

The `chm_builder` generates:

- `$WWAssociativeLinks/` as an empty logical directory.
- `$WWAssociativeLinks/Property` with 4 bytes `00 00 00 00`.

This is sufficient for compatibility with the observed reference case.

## `$FIftiMain`

`$FIftiMain` is the full-text index. It maps normalized words to topics and word positions (WLC).

### Word Extraction and Normalization

The builder indexes text from `<title>` and `<body>` of HTML topics:

- Ignores tags and content of `<script>` and `<style>`.
- Decodes basic HTML entities (`&amp;`, `&#nn;`, `&#xhh;`, etc.).
- Converts to lowercase.
- Keeps letters/digits/underscore and characters >= 128 as part of a word; others become separators.
- Maximum limit: 99 bytes per word.
- Each word has `IsTitle` (came from the title) or not.
- Positions are counted sequentially per document/topic, starting at 0.

Entry ordering:

1. `CompareStr`/binary order of the normalized word.
2. For the same word, entry with `IsTitle=true` comes before `IsTitle=false`.

### Header (1024 bytes)

The file starts with a header of `0x400` bytes. Main fields:

| Offset | Size | Type | Description |
|---:|---:|---|---|
| 0x00 | 4 | bytes | Signature `00 00 28 00`. |
| 0x04 | 4 | DWORD | `HTMLFilesCount`: indexed topics/files. |
| 0x08 | 4 | DWORD | Offset of the root node. |
| 0x0C | 4 | DWORD | Unknown, `0`. |
| 0x10 | 4 | DWORD | `LeafNodeCount`. |
| 0x14 | 4 | DWORD | Copy of the root node offset. |
| 0x18 | 2 | WORD | `TreeDepth` (1 = leaves only). |
| 0x1A | 4 | DWORD | Unknown, `7` observed. |
| 0x1E | 1 | BYTE | `DocIndexScale`, usually `2`. |
| 0x1F | 1 | BYTE | `DocIndexRootSize`, usually `1`. |
| 0x20 | 1 | BYTE | `CodeCountScale`, usually `2`. |
| 0x21 | 1 | BYTE | `CodeCountRootSize`, usually `1`. |
| 0x22 | 1 | BYTE | `LocationCodeScale`, usually `2`. |
| 0x23 | 1 | BYTE | `LocationCodeRootSize`, usually `5` in observed files. |
| 0x2E | 4 | DWORD | `NodeSize`: `4096`. |
| 0x32 | 4 | DWORD | Unknown, `0`. |
| 0x36 | 4 | DWORD | Unknown, `1`. |
| 0x3A | 4 | DWORD | Unknown, `5`. |
| 0x3E | 4 | DWORD | `LongestWordLength`. |
| 0x42 | 4 | DWORD | `TotalWordsIndexed` (total occurrences, with duplicates). |
| 0x46 | 4 | DWORD | `TotalWords` (distinct words, counting title/body as distinct entries). |
| 0x4A | 4 | DWORD | `TotalWordsLengthPart1` (total length with duplicates, per implementation). |
| 0x4E | 4 | DWORD | `TotalWordsLengthPart2`, `0` in the current builder. |
| 0x52 | 4 | DWORD | `TotalWordsLength` (length of distinct words). |
| 0x56 | 4 | DWORD | `FreeSpace` of the last leaf written. |
| 0x5A | 4 | DWORD | Unknown, `0`. |
| 0x5E | 4 | DWORD | `HTMLFilesCount - 1` or `0`. |
| 0x7A | 4 | DWORD | Windows codepage, `1252`. |
| 0x7E | 4 | DWORD | LCID. |

The unknown fields are written with values compatible with FPC/observed files.

### Nodes

All nodes have `NodeSize = 4096` bytes.

#### Leaf Node

Leaf header:

| Offset | Size | Type | Description |
|---:|---:|---|---|
| 0x00 | 4 | DWORD | Absolute `NextLeafNode`; `0` in the last leaf. |
| 0x04 | 2 | WORD | Unknown, `0`. |
| 0x06 | 2 | WORD | `FreeSpace` at the end of the node. |

Entries start at `0x08`.

#### Leaf Entry

| Field | Size | Type | Description |
|---:|---:|---|---|
| wordLen | 1 | BYTE | `1 + len(suffix)`. Can be 1 in special cases; usually >=2. |
| prefixLen | 1 | BYTE | Number of characters reused from the previous word. |
| suffix | wordLen-1 | bytes | Suffix of the word in CP1252/normalized bytes. |
| isTitle | 1 | BYTE | `1` if title, otherwise `0`. |
| docCount | var | ENCINT-BE-7 | Number of documents/topics in WLC. |
| wlcOffset | 4 | DWORD | Absolute offset of the WLC block in the file. |
| reserved | 2 | WORD | `0`. |
| wlcSize | var | ENCINT-BE-7 | Size of the WLC block in bytes. |

The complete word is `previousWord[0:prefixLen] + suffix`.

#### Index Node

Index node header:

| Offset | Size | Type | Description |
|---:|---:|---|---|
| 0x00 | 2 | WORD | `FreeSpace` at the end of the node. |
| 0x02 | ... | bytes | Index entries. |

Index entry:

| Field | Size | Type | Description |
|---:|---:|---|---|
| wordLen | 1 | BYTE | `1 + len(suffix)`. |
| prefixLen | 1 | BYTE | Prefix reused from the previous word in the same node. |
| suffix | wordLen-1 | bytes | Suffix of the word. |
| childOffset | 4 | DWORD | Absolute offset of the child node. |
| reserved | 2 | WORD | `0`. |

The index key is the last word of the corresponding child block.

#### FPC Flush Quirk

The FPC code, when flushing an index node with `NewBlockNeeded=True`, writes the block, resets the position, and writes a `DWORD 0` as a placeholder. This leaves the position at 4. The next `ChildIsFull` only writes the initial header when `Position == 0`; therefore, the next block can start with:

- `WORD freeSpace` at 0
- `WORD 0` at 2 (remnant from the placeholder)
- first entry at 4

The FPC reader considers the free space by the WORD at 0 and traverses entries starting from 2; in practice, the entry at 4 falls within the valid range. The `chm_builder` reproduces this layout for compatibility with the reader/hh.exe.

### WLC (Word Location Codes)

Each leaf entry points to a WLC block. The WLC contains, per document, the topic delta, number of occurrences, and position deltas.

For each document, in order:

1. `DocDelta = topicIndex - lastDocIndex`, encoded with `ScaleRoot(DocIndexRootSize)`.
2. `NumCodes = number of positions`, encoded with `ScaleRoot(CodeCountRootSize)`.
3. For each position: `LocDelta = position - lastLocCode`, encoded with `ScaleRoot(LocationCodeRootSize)`.
4. `ClearBuffer`: bits are aligned to the next byte after each document.

Initial values: `lastDocIndex = 0`, `lastLocCode = 0` for each document.

### ScaleRoot Encoding

`WriteScaleRootInt` (FPC) generates MSB-first bits:

- `NeededBits = bitLength(value)`.
- `PrefixBits = max(0, NeededBits - RootSize)`.
- `RootBits = max(NeededBits - 1, RootSize)`.
- `Mask` has `RootBits` low bits set.
- `Bits = ((~Mask) << 1) | (value & Mask)`, with room for one zero separator bit.
- `Total = PrefixBits + 1 + RootBits`.
- Output is written MSB-first in the bit stream.

Reading (`ReadWLC`):

- Reads the initial bit and saves it as the most significant bit of the result.
- Counts consecutive `1` bits as prefix, until finding `0`.
- Consumes the `0` separator.
- Reads `RootSize + max(PrefixBits - 1, 0)` remaining bits, shifting the result left.
- `ClearBuffer` discards remaining bits of the current byte after each document.

### ENCINT-BE-7 in `$FIftiMain`

Used for `docCount` and `wlcSize` in leaves:

- Value is decomposed into 7-bit groups, least-significant group first.
- Each byte carries 7 bits in the low field; bit 7 is set in all bytes except the last.
- Example: `130 = 0x82` in low 7 bits + `0x01` in the next group => bytes `82 01`.

Note: this format is different from the CHM directory ENCINT.

## Relationship with `#SYSTEM`

The `#SYSTEM` entry code 4 contains a 36-byte block with observed flags/fields. The builder fills:

- offset 0: LCID
- offset 4: DBCS/observed flag
- offset 8: full-text present (`1` if `$FIftiMain` not empty)
- offset 12: KLinks present (`1` if there are keywords)
- offset 16: ALinks (`0`)
- offset 20/24: timestamp/observed values

## Practical Validation

For the example `../example`:

- `$OBJINST` and `$WWKeywordLinks/{BTree,Data,Map,Property}` are byte-identical to the HHC reference.
- `$FIftiMain` is decodable by the FPC reader semantics: 32 words, topics 0..2, coherent positions.
- `hh.exe` opens the generated CHM.
- The test with libmspack (`make test LIBMSPACK=...`) passes.
